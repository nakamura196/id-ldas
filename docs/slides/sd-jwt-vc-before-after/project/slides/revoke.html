変わる仕組み 1

失効：before では、他所の検証で取り消しが効かなかった

Before

検証する側が、IETF 式の status 欄を探す

見つからない（W3C 式の名前で書いてある）

エラーにならず、失効の確認を飛ばす

取り消した会員証でも通ってしまう

After

status 欄を見つける（idx 2）

/status/token/1 を取りに行き、発行元の署名を確かめる

リストの 2 番目のビットを読む

0 なら有効、1 なら拒否する

walt.id の検証サーバ（1.2.0）で、同じ形の会員証を使って実測した。

いちばん大きな問題はここ。失敗ではなく「確認を飛ばす」なので、気づきにくい。
